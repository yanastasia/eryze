# Eryze Projects Designer Brief

## Purpose

This document explains how Eryze projects should be presented by a web designer across the site.

It is not a raw content dump. It is a visual and narrative brief for:

- homepage work sections
- studio and labs listing pages
- individual project detail pages
- supporting social, portfolio, and presentation layouts

Source of truth for project content:

- [data/projects.ts](/Users/anastasia/Projects/Github/eryze_web/data/projects.ts)

## Core principle

Projects should present Eryze as a studio that brings clarity to complexity.

Each project should feel:

- structured
- credible
- specific
- outcome-aware
- visually distinct from the others

They should not feel:

- like interchangeable SaaS cards
- like Behance-style decoration-first case studies
- overly startup-hyped
- visually noisy

## Project system

There are currently four projects in the Eryze site data.

### Studio projects

- `Pautalia Residence`
- `Acting Europe`

These represent client-facing delivery work.

They should communicate:

- launch readiness
- trust
- execution discipline
- strong information architecture

### Lab projects

- `KidsGo`
- `Livrea`

These represent internal product work.

They should communicate:

- product thinking
- system design
- iteration
- strategic depth

## Cross-project presentation rules

### 1. Show the system, not just the screen

Project pages should never rely only on pretty mockups.

They should show:

- what problem existed
- what structure was introduced
- who the system serves
- what changed as a result

### 2. Keep the hierarchy editorial

Use:

- strong headline
- compact supporting summary
- structured information bands
- clear sections for problem, goal, solution, built areas, stack, and outcome

Avoid:

- long walls of copy
- card piles
- floating decorative blocks with no hierarchy

### 3. Let each project have its own sub-mood

All projects should still belong to the Eryze brand system, but each one needs a slightly different visual read.

The distinction should come from:

- image selection
- crop choices
- spacing density
- supporting accent emphasis
- section composition

It should not come from inventing a completely new brand per project.

### 4. Motion stays quiet

Project pages can use subtle ambient motion, but it should never interfere with legibility.

Use:

- soft drift
- horizon glow
- restrained transitions

Avoid:

- animated diagrams everywhere
- busy lines behind text
- attention-grabbing showcase effects

## Recommended case study structure

Each full project page should follow this sequence.

1. Hero
2. Quick overview
3. Problem
4. Goal
5. Solution
6. What was built
7. Technical foundation
8. Outcome
9. Learnings
10. Next project or CTA

### Hero requirements

The hero should establish:

- what the product/system is
- who it is for
- why it matters

The hero should feel immediate and composed, not abstract.

### Overview requirements

Every project should clearly show:

- `Who`
- `What`
- `Role`

These are practical anchors and should be easy to scan.

### Built section requirements

The `Built` section is where the designer can create the strongest structural storytelling.

This area should emphasize subsystems and roles, not just features.

## Listing page rules

### Homepage

The homepage should show only selected work.

The goal is not completeness. The goal is credibility and range.

Recommended balance:

- 2 studio/client-facing examples
- 2 internal/lab examples

### Studio page

The studio page should feel more delivery-oriented and commercial.

Lead with:

- clarity
- launch readiness
- information architecture
- operational trust

### Labs page

The labs page should feel more product-minded and exploratory, but still disciplined.

Lead with:

- systems thinking
- sequencing
- user behavior
- iteration logic

## Project-by-project art direction

This is one of the clearest proof points for Eryze as a premium client delivery studio.

It shows:

- real estate structure
- browsing clarity
- visual precision
- premium but usable presentation

### What the design should emphasize

- architectural clarity
- property exploration
- floor and apartment navigation
- bilingual structure
- high-trust presentation

### Visual mood

- refined
- spatial
- calm
- premium
- precise

### Designer notes

Use compositions that highlight:

- plans
- spatial browsing
- structured navigation
- inventory clarity

This project should feel polished and composed, not luxurious for its own sake.

Avoid:

- glossy real-estate clichés
- oversized lifestyle filler
- gold, beige, or warm premium cues

## 2. Acting Europe

### Strategic role

This project proves Eryze can handle a live public-facing content platform with cultural depth.

It shows:

- content-heavy architecture
- bilingual navigation
- public-facing usability
- launch-ready implementation

### What the design should emphasize

- events
- venues
- cultural discovery
- browseability
- editorial clarity

### Visual mood

- cultural
- editorial
- layered
- public-facing
- intelligent

### Designer notes

This project can carry a slightly more editorial tone than the others.

Use layouts that suggest:

- browsing richness
- programming density
- content structure

Avoid making it feel like:

- a ticketing app clone
- a museum brochure
- a generic listings UI

## 3. KidsGo

### Strategic role

This is a strong example of Eryze as a product systems thinker.

It shows:

- multi-role product logic
- moderation and operations thinking
- booking flow structure
- platform strategy

### What the design should emphasize

- parent discovery
- organizer workflows
- admin control
- trusted marketplace logic

### Visual mood

- structured
- active
- accessible
- clear
- operational

### Designer notes

This project should not look childish.

It serves children-related use cases, but the actual product logic is about trust, operations, and coordination.

Use:

- structured dashboards
- controlled marketplace signals
- category and booking clarity

Avoid:

- playful illustrations as the main read
- primary-school aesthetics
- bright multicolor product language

- focus

- calm

## Relative project roles on the site

If the designer needs a hierarchy for emphasis, use this order:

1. `Pautalia Residence`
2. `KidsGo`
3. `Livrea`
4. `Acting Europe`

Reasoning:

- `Pautalia Residence` is the strongest immediate commercial proof
- `KidsGo` shows strategic and technical platform depth
- `Livrea` adds product refinement and differentiation
- `Acting Europe` adds public cultural platform credibility

This order can change later, but it is a solid current default.

## Thumbnail and preview guidance

Project cards and preview areas should avoid looking uniform.

Each card should signal its domain quickly.

### Best cues by project

- `Pautalia Residence`: floorplans, property views, filtered apartment browsing
- `Acting Europe`: event discovery, venue structure, cultural listings
- `KidsGo`: role-based flows, activity discovery, booking/ops states
- `Livrea`: reading sessions, library states, progress/highlight structure

### Card design rules

- use one strong visual cue, not many
- pair the cue with a precise headline
- keep metadata compact
- preserve strong contrast and calm spacing

## Copy direction for project presentation

Project copy should sound:

- exact
- calm
- capable
- business-aware

Use language like:

- `Structured browsing for homes, floors, and apartments.`
- `A multi-role platform for parents, organizers, and admins.`
- `A calm reading product connecting sessions, libraries, and progress.`

Avoid language like:

- `Revolutionary`
- `Cutting-edge`
- `Innovative experience`
- `Next-generation platform`

## Asset requests for the designer

If the designer is preparing layouts or mockups, the most useful project assets are:

- homepage screenshots
- dashboard or system screenshots
- flow or structure views
- mobile screens where relevant
- floorplan and map interfaces where relevant

Priority is not flashy renders.

Priority is screens that reveal:

- hierarchy
- information structure
- interaction logic
- product maturity

## Final instruction

The Eryze projects should feel like one studio showing range, not four unrelated brands.

The designer should preserve:

- the Eryze dark-first editorial system
- calm premium technical tone
- structured storytelling
- subtle visual differentiation between projects

If a design choice makes a project look more decorative than credible, it is the wrong choice.
